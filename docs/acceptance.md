# PRD acceptance evidence

This maps the approved PRD AC-01–17 to actual checks. Core tests are in `packages/core/test`, adapter tests in `apps/web/test/unit`, production browser checks in `apps/web/test`, and CLI subprocess checks in `packages/cli/test`. The isolated Phase 2 harness is excluded from release builds. Final command results are recorded in [testing](testing.md).

- **AC-01:** `lexer`, `parser`, `semantic`, `lower`, `analyze`, `codegen` and fixture tests cover the complete stage prefix, spans/IDs, valid examples and empty HALT bytecode. Production runtime tests require completed analysis and verified bytecode.
- **AC-02:** Semantic/lexer/parser/template/fixture tests cover independently expected blocking errors. The production invalid-source test disables Run and removes runnable bytecode.
- **AC-03:** Taint/provenance tests and the independent evaluation cover direct, transitive, merged and multiple-source contributions, exactly one finding per sink argument/rule and exact source attribution.
- **AC-04:** Taint fixtures cover trusted overwrite, predecessor union and zero-iteration loops. Independent evaluation includes overwrites and a loop with a structurally preserved incoming contribution.
- **AC-05:** Lower/codegen/VM/runtime fixtures cover short circuit, including skipped input. Evaluation retains false alarms from structural infeasibility and documents this limitation.
- **AC-06:** Semantic/taint fixtures and the production unsafe-to-binding demonstration cover bound-value exclusion, tainted templates, literal placeholder errors and nonliteral uncertainty notices.
- **AC-07:** Solver/provenance/replay tests cover finite source identities, deduplicated work, cycles, exact count/byte caps, cancellation and fake-clock deadlines. Presentation truncation does not change converged findings.
- **AC-08:** Source adapters, replay and production finding/bytecode selection checks cover exact mapping and reconstruction. The production release test reaches the real replay byte cap with 200 initialized declarations, verifies the truncation label and returns to usable final analysis. Core provenance truncation tests verify retained source contributions; not every provenance display cap was reached interactively.
- **AC-09:** Reducer/worker tests inject stale, duplicate, malformed, failed, cancelled and watchdog outcomes. Production release checks verify visible analysis cancellation/retry, source edit during processing, previous-snapshot exports, invalid source, runtime states and input errors. State injection tests complement real workers; they are not proof of every OS failure mode.
- **AC-10:** Codegen/verifier/VM tests cover every opcode, malformed operands/mappings/types, stack joins, initialization convergence, exact arithmetic and short-circuit execution. Real browser workers and CLI transport verified bytecode.
- **AC-11:** VM/CLI/runtime fixtures check typed deterministic input/print/query/binding/shell events, errors retaining prior events and fixed limits. Production network interception and text-injection checks verify no external application calls and text rendering. No real SQL/shell service exists.
- **AC-12:** Shared core/CLI tests and actual sample reports validate identity/version/limits, report schemas, exit precedence, exact analyzed source, JSON/Markdown fences and no-clobber outputs. Production exports carry matching runtime only; edited-source Markdown excludes stale execution.
- **AC-13:** Production workspace checks cover dirty replacement, save/cancel/discard, BOM/newline/Unicode round trips and file failures preserving drafts. Release checks inspect empty local/session storage and verify empty reload/no automatic run.
- **AC-14:** Budget/core tests use cap and cap+1 or strictly lowered private test budgets, without exposing budget changes to release users. Layout client tests and the isolated forced-failure harness cover timeout/malformed/failure fallback. Production >200-node list retains semantic edges. Report failure tests preserve results; stale bytecode cannot run.
- **AC-15:** Fresh npm installation and production builds were executed. Offline-origin production checks block remote calls, and keyboard/manual replay/reduced-motion tests use the release bundle. The full workspace is intended for desktop viewports; a formal assistive-technology certification is not claimed.
- **AC-16:** `scripts/benchmark.ts` measures 20 fixed-seed bounded engine workloads, ten repeats after one warm-up, and an actual 200-node graph. Raw hardware, source hashes, stage/total times, readiness, layout/render interval, selection and both cancellation paths are retained in [benchmark evidence](evidence/benchmark.json). Targets are unchanged. See [evaluation](evaluation.md) for the measured outcome.
- **AC-17:** [Remote CI run 37660826256](https://github.com/harshshah-24/FlowGuard/actions/runs/37660826256) passed for published implementation `9b3e96c`. Phase 4 local checks are separate; remote CI for Phase 4 can only be verified after authorized publication. No project LICENSE is added. README, report and handoff state this boundary.
